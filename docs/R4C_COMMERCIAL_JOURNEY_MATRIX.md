# R4C Commercial Journey Matrix

| Journey | Starting point | Context | Actions | Permission boundary | Evidence generated | State transition | Failure state | Next-best-action | Completion condition |
|---|---|---|---|---|---|---|---|---|---|
| A. Executive to affected units | Command Center decision queue | Selected project, snapshot freshness, exception reason | Open project, inspect portfolio row, open unit control, select building/floor/unit | Commercial read; project/unit access remains tenant-scoped | Exportable snapshot and selected-unit evidence | Portfolio exception → project context → unit context | Snapshot is stale or live aggregation unavailable | Review live inventory or connect approved aggregation | User reaches the affected unit with context preserved |
| B. Lead to recorded interest | Sales operations capture form | Tenant, owner, buyer consent, selected project | Capture lead, qualify, choose project/unit, review buyer evidence, record interest | Lead creation and qualification permissions; consent required | Buyer contact, source, consent, activity, interest record | New → contacted/qualified → interest | Missing required fields, missing consent, unauthorized action, no available unit | Complete consent or select an available unit | Interest is recorded against buyer and unit |
| C. Unit to hold to reservation | Buyer/unit workspace | Buyer, unit, published price, payment plan, hold expiry | Select available unit, create hold, review price/payment plan, confirm reservation | Hold create/release and reservation confirmation permissions; server gates | Hold record, price snapshot, payment-plan review, reservation result | Available → held → reservation review → confirmed | Unit unavailable, hold expired, no price/payment plan, review unchecked | Refresh state or release/reselect unit | Authorized reservation confirmation returns from server |
| D. Reservation to closing readiness | Reservation result or transfer queue | Buyer, unit, value, evidence, readiness state | Review documents, request missing evidence, verify checklist, inspect audit timeline | Document/readiness actions remain authorized; no legal overclaim | Checklist status, evidence attachments, request/approval trail | Reservation → evidence review → readiness state | Missing RETT reference, mortgagee approval, buyer IBAN, government review | Request document or escalate blocker | File is ready for approved handoff or explicitly blocked |
| E. Sold unit to title transfer | Closing queue | Sold unit, buyer, value, blocker, owner, age | Open transfer file, resolve blocker, approve readiness, use controlled handoff action where supported | Admin/closing permissions; government submission only through approved integration | Transfer checklist, evidence, approval state, timeline | Sold → transfer review → ready/blocked → controlled handoff | Missing evidence, government review, no approved integration | Request missing document or escalate | Readiness is approved and handoff is explicitly governed |

## Cross-journey invariants

Every journey must preserve project, buyer, unit, owner, provenance, and permission context. Canonical IDs must remain unchanged across English and Arabic. Snapshot and preview values must not be presented as governed live records. Failure states must be actionable and must not silently mutate data. When a workflow requires a backend capability that does not exist, the UI should show a documented dependency rather than inventing a fake action or integration.
